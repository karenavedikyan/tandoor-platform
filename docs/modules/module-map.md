# Карта модулей

## Статусы видимости модулей

В паспорте каждого модуля фиксируется **статус видимости** в продукте:

1. **internal_prototype** — внутренний каркас и прототип; в навигации для внешних тестировщиков **не показывается**.
2. **preview** — согласованный этап для приёмки; показывается тестировщикам по чек-листу.
3. **beta** — ограниченная группа пользователей с явным статусом «бета».
4. **production** — промышленная эксплуатация для ролей согласно правам.

**Внешним тестировщикам** доступны только модули (и экраны) в статусах **preview**, **beta** или **production** — и только в рамках текущего этапа. Подробнее: [Preview-режим Tandoor Platform](../architecture/preview-mode.md).

## Безопасность и управление доступом

Назначение: сквозные правила доступа, секретов и демонстрации платформы клиентам, дилерам, менеджерам, регионалам, руководителям и другим ролям при интеграциях с **1С**, **Bitrix**, **Bitrix24**, **Excel/Google** и текущим **Bitrix-сайтом**.

Состав:

1. Роли и права (**RBAC**).
2. **Preview mode** и поэтапное раскрытие навигации (см. [Preview-режим](../architecture/preview-mode.md)).
3. **Audit log** — журнал значимых действий и доступа к чувствительным данным.
4. **Secret management** — секреты только в ENV, GitHub Secrets, Vercel Env и закрытых хранилищах; не в git (см. [Безопасная разработка](../security/development-security.md)).
5. **Data masking** — обезличивание в логах, отчётах и непродакшен-стендах (целевое развитие).
6. **Demo data mode** — фиктивные наборы для dev и тестов; запрет реальных PII в публичном репозитории.

## База знаний и обучение

Назначение: единое хранилище знаний о продукте и продажах с разграничением доступа для дилеров и сотрудников Tandoor.

MVP:

1. Внутренняя Wiki по продукту (структура, поиск, версии).
2. Витрины «для дилера» и «для менеджера».
3. Разделы: техника продаж, скрипты, работа с возражениями.
4. Учёт прочтений ключевых материалов.
5. Задел под тесты и сертификацию (модель попыток и проходного балла).

Интеграции: при необходимости чтение или импорт черновиков из Google Документов до переноса контента в платформу.
