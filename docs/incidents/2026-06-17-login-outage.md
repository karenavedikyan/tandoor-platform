# Постмортем — 17.06.2026 — Простой логина в проде

**Серьёзность:** P0 — пользователь полностью заблокирован.
**Длительность простоя:** ~40 минут.
**Затронуто:** все пользователи прода `tandoor-platform.vercel.app`.
**Корень проблемы:** ридер сессии, заменённый в PR #751, не находил пользователя по cookie. Регрессия попала в прод, потому что в CI не было e2e-проверки «login → /api/auth/me».

## Корневая причина

PR #751 (Промт 380 — bootstrap endpoint + LRU cache + ETag) сделал три изменения, два из которых оказались взаимоувязаны:

1. **Заменил `handleMe(headers)` на `resolveSessionUserRow(pool, headers)`** в `apps/platform/api/auth/[action].ts`. Новый ридер живёт в `shared/auth-me-read.ts` и читает сессию по-другому — он не нашёл сессию по присланному cookie. Эндпоинт ушёл в 401.
2. **Завернул `/api/auth/me` в LRU-кэш через `serveCachedJson`**. Кэш кешировал только успешные ответы (`shouldCache: success === true`), поэтому 401 не закрепился, но и не помогал — каждый запрос всё равно валился в новом ридере.
3. **Завернул `/api/auth/my-visible-codes` и `/api/auth/my-org-snapshot`** в тот же кэш. Те же 401 шли по той же причине.

`BOOTSTRAP_CACHE_ENABLED=false` отключал только LRU-кэш, а не сам ридер — поэтому флаг не помог.

**Почему ловушка пробила CI.** В `test:ci-smoke` был `test:auth-access` (юнит-проверка), но не было e2e-теста «логин → me → 200» против реального API. Существующий `test:auth-e2e` не входил в ci-smoke и шёл от login сразу к `/api/invitations/create`, минуя `/api/auth/me`.

## Вторичная проблема (после ревёрта)

В `App.tsx` уже давно вызывались `setRealScopeAuditUserId(user.id)` и `attachRealScopeAuditUnloadFlush()` — **без явного импорта**. Импорта не было ни до PR #751, ни в самом PR #751, ни в PR #754. Функции «жили» через косвенную цепочку (что-то транзитивно импортировало модуль и оставляло символы видимыми Vite-бандлу). Когда я делал revert PR #751, удалились `shared/auth-me-read.ts`, `bootstrap-handler.ts` и др. — цепочка распалась, символы стали undefined, **клиент крашился сразу после логина → белый экран на всех устройствах.**

Это был скрытый долг — `App.tsx` опирался на удачу. Исправлено двумя строками импорта в `App.tsx` (`338c0cb`, `b0afd1d`).

5. `test:ci-smoke` дополнен `test:cookie-roundtrip` в самом конце цепочки.

## Чек-лист для будущих изменений auth/session

Перед мержем любого PR, который трогает `apps/platform/api/auth/*`, `shared/auth-*`, `server/sessions/*`:

- [ ] **Не заменять рабочие `handle*()` целиком.** Если нужен кэш — оборачивай поверх существующей функции (декоратор), не сбоку.
- [ ] **Не кэшировать `/api/auth/me`.** Этот эндпоинт — единственный источник правды для клиента после login. Кэш на нём ловит cookie-baseline и ломает switch-аккаунта, impersonation, выход.
- [ ] **Запустить `test:cookie-roundtrip` против превью-деплоя** перед мержем. Без зелёного шага 101 — не мержить.
- [ ] **Проверить, что cookie в `set-cookie` совпадает с тем, что эндпоинт ожидает читать.** Имя, путь, `HttpOnly`, `SameSite`.
- [ ] **Playwright под превью** — login → дашборд должен отрендериться без `pageerror`.
