# Навигация директора и РОПа (sidebar / mobile)

## Зачем упрощённая структура

Меню **не дублирует** «главную», карточку территории и второстепенные блоки: в фокусе остаются **рабочие зоны текущего этапа** — статистика актуализации клиентской базы, дилеры, торговые точки и **план-факт / KPI**. Остальные разделы собраны в группу **«В разработке»**: они **по-прежнему открываются по реальным маршрутам** (без замены страниц заглушками), но визуально помечены как нефинальные, чтобы ожидания были прозрачны.

Группа-аккордеон **«Клиентская база»** убрана: внутри было всего три рабочих пункта, лишний уровень мешал быстрому доступу. Рабочие разделы показаны **сразу верхним плоским списком** в том же визуальном стиле, что и остальные pilot-пункты; **единственный** оставшийся аккордеон — **«В разработке»**.

Менеджер (`sales_manager`), маркетолог, аналитик и прочие роли используют **прежнюю плоскую** модель навигации — она **не менялась**.

## Структура (директор и РОП одинаково)

| Блок | Содержимое |
|------|------------|
| **Рабочие разделы** (плоский список, без группы-обёртки) | Статистика обновления базы → `/client-base-activity`; Клиенты-дилеры → `/dealer-base` (+ badge); Торговые точки → `/trade-points` (+ badge); План-факт и KPI → `/sales-control/plan-fact` |
| **В РАЗРАБОТКЕ** (группа, аккордеон) | Каталог, обучение, карта клиентов, задачи по витрине, аналитика команды, коммуникации, маркетинговые брифы — **текущие** URL разделов; у каждого пункта muted-бейдж «в разработке» |

Маршрут **`/territory-card`** по политике доступа может оставаться доступным (например с прямой ссылки или закладки), но **в меню директора/РОПа не показывается**.

## Счётчики

Счётчики активных клиентов и ТТ для **Клиенты-дилеры** / **Торговые точки** считаются так же, как раньше (scope по роли в данных актуализации). Числа отображаются **только в бейджах** соответствующих пунктов верхнего списка.

## Аккордеон

Поведение только для `layout: "grouped"` в `AppShell`.

| Группа | По умолчанию (пустой `localStorage`) |
|--------|--------------------------------------|
| В разработке | Свернута, если нет активного пункта внутри |

Если текущий URL соответствует пункту внутри группы, группа **автоматически раскрывается** (в том числе после ручного сворачивания до перехода на маршрут из этой группы).

Ключ **`localStorage`**: `tandoor-pilot-sidebar-open-groups-v1`. Сохраняются только ключи существующих групп текущей модели; устаревшие ключи (в т.ч. **`client-base`** от прошлых версий) **не используются** — при чтении учитываются только группы из `model.groups`.

## Техническая реализация

- Модель: `getPilotNavigation` → `PilotNavigationModel` в `auth-access.ts` (`layout: "flat" | "grouped"`; для директора/РОПа: `leadingItems` — верхний плоский блок, `groups` — только `in-development`; опционально `standaloneItems` для совместимости других grouped-сценариев).
- UI: `AppShell` / `NavigationPanel` / `PilotNavGroupedList` — при наличии `leadingItems` сначала рендерится плоский блок рабочих пунктов, затем аккордеоны по `groups`.
- `getPilotNavItems` / `flattenGroupedPilotNavigation` — плоский порядок: `leadingItems` → `standaloneItems` → все пункты групп (иконки rail).
