# Навигация директора и РОПа (sidebar / mobile)

## Зачем упрощённая структура

Меню **не дублирует** «главную», карточку территории и второстепенные блоки: в фокусе остаются **рабочие зоны текущего этапа** — **клиентская база** (актуализация, дилеры, точки) и **план-факт / KPI**. Остальные разделы собраны в группу **«В разработке»**: они **по-прежнему открываются по реальным маршрутам** (без `/feature-in-development` и без замены страниц заглушками), но визуально помечены как нефинальные, чтобы ожидания были прозрачны.

Менеджер (`sales_manager`), маркетолог, аналитик и прочие роли используют **прежнюю плоскую** модель навигации — она **не менялась**.

## Структура (директор и РОП одинаково)

| Блок | Содержимое |
|------|------------|
| **КЛИЕНТСКАЯ БАЗА** (группа, аккордеон) | Статистика обновления базы → `/client-base-activity`; Клиенты-дилеры → `/dealer-base` (+ badge); Торговые точки → `/trade-points` (+ badge) |
| **План-факт и KPI** | Отдельный пункт меню (не группа) → `/sales-control/plan-fact` |
| **В РАЗРАБОТКЕ** (группа, аккордеон) | Каталог, обучение, карта клиентов, задачи по витрине, аналитика команды, коммуникации, маркетинговые брифы — **текущие** URL разделов; у каждого пункта muted-бейдж «в разработке» |

Маршрут **`/territory-card`** по политике доступа может оставаться доступным (например с прямой ссылки или закладки), но **в меню директора/РОПа не показывается**.

## Счётчики

Счётчики активных клиентов и ТТ для **Клиенты-дилеры** / **Торговые точки** считаются так же, как раньше (scope по роли в данных актуализации). В сводке заголовка группы «Клиентская база» при наличии данных показывается строка вида `40 клиентов · 45 ТТ`.

## Аккордеон

Поведение только для `layout: "grouped"` в `AppShell`.

| Группа | По умолчанию (пустой `localStorage`) |
|--------|--------------------------------------|
| Клиентская база | Раскрыта |
| В разработке | Свернута, если нет активного пункта внутри |

Если текущий URL соответствует пункту внутри группы, группа **автоматически раскрывается** (в том числе после ручного сворачивания до перехода на маршрут из этой группы).

Ключ **`localStorage`**: `tandoor-pilot-sidebar-open-groups-v1`. Сохраняются только ключи существующих групп; устаревшие ключи из прошлых версий меню **игнорируются** при чтении.

## Техническая реализация

- Модель: `getPilotNavigation` → `PilotNavigationModel` в `auth-access.ts` (`layout: "flat" | "grouped"`; для grouped опционально **`standaloneItems`** — пункты между первой группой и остальными, порядок в rail задаётся через `flattenGroupedPilotNavigation`).
- UI: `AppShell` / `NavigationPanel` / `PilotNavGroupedList` — группы с переключателем, отдельный блок пунктов для «План-факт и KPI».
- `getPilotNavItems` — плоский список в порядке: пункты первой группы → `standaloneItems` → пункты остальных групп (иконки rail).
