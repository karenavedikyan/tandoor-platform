# Логические группы карточек клиента (MVP)

## Зачем нужны группы

В клиентской базе одна и та же организация может приходить несколькими строками (разные коды, связанные ИП, дубли из выгрузок). Для работы менеджера удобнее видеть **одну логическую строку** в списке и иметь в карточке обзор всех связанных исходных записей, не ломая интеграции.

## Почему исходные карточки не удаляются

Карточки могут быть связаны с **1С**, **Bitrix24**, историей синхронизации и отчётами. MVP **не** перезаписывает и не удаляет исходные строки данных — только добавляет слой «объединение» поверх них.

## Где хранится состояние

- **Ключ localStorage:** `tandoor-dealer-client-groups-v1` (константа `DEALER_CLIENT_GROUPS_STORAGE_KEY` в `client/src/lib/dealer-client-groups.ts`).
- **Событие обновления UI:** `tandoor-dealer-client-groups-changed` (`DEALER_CLIENT_GROUPS_EVENT`) — после сохранения диспатчится `CustomEvent`, чтобы список и карточка подхватили изменения без перезагрузки страницы.

## Ограничения MVP

- Группы привязаны к **`personaUserId`** текущего пользователя демо-профиля: это **личный** слой для менеджера / РОПа / директора, чтобы не затрагивать общую базу до появления серверной модели.
- **Маркетолог / аналитик** в этом шаге не создают и не редактируют группы; видимость чужих групп по `userId` не синхронизируется — у разных ролей набор групп может не совпадать.
- Фильтрация списка по-прежнему считается **по отдельным строкам**, затем строки **сворачиваются** в одну на группу; визуально и в счётчике «Показано N» группа считается **одной строкой**.
- Текстовый поиск учитывает **всех участников** активной группы (если совпал любой — в фильтр попадает строка, отображаемая как primary с названием группы).

## Как пользоваться (кратко)

1. **Создание:** в клиентской базе выберите **2+** клиента (чекбоксы), нажмите **«Объединить в клиента»**, заполните название, выберите основную карточку, при необходимости комментарий, подтвердите **«Объединить»**.
2. **Список:** группа показывается **одной строкой** (основная карточка), с бейджем объединения и кодами всех участников; **«Открыть»** ведёт на карточку primary с параметром `?clientGroupId=...`.
3. **Карточка:** блок **«Связанные карточки клиента»** — название группы, основная карточка, комментарий, список связанных с переходами.
4. **Редактирование:** кнопка **«Редактировать объединение»** (менеджер / РОП / директор в рамках MVP).
5. **Разъединение:** **«Разъединить»** — только **РОП** или **директор**; группа **архивируется** (`archivedAt`), данные не удаляются, карточки снова видны по отдельности.

## Будущее: backend и интеграции

Имеет смысл перенести на сервер: единый идентификатор группы, права по ролям и scope команды, согласование с **1С / Bitrix24** (matching по ИНН, контрагенту, правилам дедупликации), аудит и синхронизация между пользователями.
